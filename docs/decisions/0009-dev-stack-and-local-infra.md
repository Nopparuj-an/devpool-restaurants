# 0009 — Dev stack and local infrastructure

**Status:** Accepted (2026-09-26)

## Decision
- **Go:** stdlib `net/http` routing (Go 1.22+ method patterns) and `log/slog`, with no web framework. `pgx/v5` pool. `goose` migrations are embedded in the binary and applied on API start. Queries are **hand-written SQL with pgx** (amended 2026-09-26). sqlc was dropped because it needs a cgo Postgres parser and pulls a large dependency tree, and plain SQL is easier to walk through in the interview.
- **Frontend:** pnpm, Next.js App Router, Tailwind + shadcn/ui (revisit after the `/design` gallery, ADR-0008).
- **Local infra:** `deployment/docker-compose.yml` runs Postgres 18 and Garage v2.4.1. All state is **bind-mounted under `deployment/data/`** (gitignored). The Go API and Next.js run on the host during development.
- **Secrets:** `deployment/.env` is generated by `make env` from `.env.example` and is never committed.
- **Tasks:** a root `Makefile` (`make help`).
- **Tests:** pure logic uses table tests. Integration tests (`internal/apitest`) run the full HTTP API against a **throwaway database** created on the compose Postgres for each test and dropped afterwards. `make test` sets `TEST_DATABASE_URL`, and without it they are skipped.

## Consequences
- Resetting all data is `make down && rm -rf deployment/data`.
- Ports are bound to 127.0.0.1 only: 5432 (Postgres), 3900 (S3 API), 3902 (public images), 8080 (API).
- The API and web app containers are covered by [ADR-0010](0010-containers.md).
